② 深入浅出

一、手写题通用套路：先打灯，再起步，最后靠边

手写题挂掉的人，多半不是「不会写」，而是上来就写。通用的三步节奏是：

  • 第一步 · 确认边界：动笔前先和面试官对齐需求——「深拷贝需要处理 Map/Set 吗？数据里有循环引用吗？防抖要支持立即执行吗？」这一步既是收集信息，也是展示工程素养，说一句「我先确认一下边界」面试官印象分立刻上来。
  • 第二步 · 主干逻辑：先写出能覆盖最常见场景的最小实现（对象递归、定时器关闭重开、参数收集），别追求一步到位。
  • 第三步 · 补防御：回头补 null 判断、原型链属性、取消功能等边界，边补边讲「这里如果不处理会发生什么」。

二、防抖与节流：闭包是它们的发动机

两个词解决的是同一个问题——事件触发太频繁，但策略相反：

  • 防抖（debounce）：等触发停止后再执行。每次触发都重置定时器，只有「安静满 wait 毫秒」才真正执行。适合等用户停下来的场景：搜索框输入联想、窗口 resize 后重算布局。
  • 节流（throttle）：固定频率执行。不管触发多密，每 wait 毫秒最多执行一次。适合持续动作保底频率的场景：滚动加载、拖拽跟随、鼠标移动。
function debounce(fn, wait) {
  var timer = null;                  // 闭包变量：定时器被「关」在返回函数的作用域里
  return function () {
    var args = arguments;
    clearTimeout(timer);             // 每次触发：先拆掉上一次的闹钟
    timer = setTimeout(function () { // 再设一个新闹钟——只有连续 wait 毫秒没人触发才会响
      fn.apply(this, args);
    }, wait);
  };
}

为什么必须用闭包？因为 timer 要跨越多次调用存活：外部每次触发拿到的是同一个返回函数，它记得上一次的闹钟，才能拆掉重设。如果 timer 写在函数内部，每次触发都新建一个，等于每次都拆自己的新闹钟，防抖就失效了。进阶版加两个能力：immediate（第一次立即执行，之后才进入等待）和 cancel（返回一个取消函数，清掉定时器）。

三、深拷贝：递归与「为什么 JSON 那招不够」

先弄清「浅」与「深」：赋值和 Object.assign 只复制第一层——第一层如果是对象，复制过去的只是引用地址，改克隆体内部，原件照样受伤，这是浅拷贝。 深拷贝要递归：遇到对象就新建一个空对象，遇到数组就新建空数组，然后逐个成员继续问「你是基本类型还是引用类型」，直到全是基本类型为止。 很多人用 JSON.parse(JSON.stringify(obj)) 应付——它能处理纯数据对象，但有硬伤：函数和 undefined 直接消失、Date 变成字符串、RegExp 变空对象、Map/Set 变空壳、遇到循环引用直接抛错。所以面试要求手写时，用的是递归版：

  • 出口条件：value === null || typeof value !== 'object' 时直接返回——注意必须先判 null，因为 typeof null === 'object' 是 JS 的历史 bug，不先拦住它，null 会被当成对象继续递归。
  • 数组分支：Array.isArray(value) 用 map 逐项递归，保证拷出来还是数组。
  • 对象分支：遍历自身可枚举属性（用 hasOwnProperty 排除原型链上的属性），逐键递归。
  • 循环引用：如果 A 引用 B、B 又引用 A，朴素递归会无限套娃直到栈溢出。解法是开一张 WeakMap「已拷登记表」：拷贝前先查表，同一个引用在同一轮拷贝里只建一次副本，再次遇到直接复用——这也是面试最高频的追问点。

四、柯里化：参数收集游戏

柯里化（curry）把 f(a, b, c) 变成可以 f(a)(b)(c)、也接受 f(a, b)(c) 的形式。本质是一个收集参数的游戏： 返回的函数每被调用一次，就用闭包把收到的参数攒起来，够数（达到原函数的形参个数，即 fn.length）就执行，不够就再返回一个「记得已收参数」的新函数接着收。 为什么判断用 >= 而不是严格相等？因为参数可以一次传多个（f(1,2)(3)），攒够就执行。 它的实际价值在参数复用：log = curry(function(tag, msg){...}) 之后，logWarn = log('警告') 就得到一个「只管发警告」的新函数——固定了第一个参数，这正是函数式编程里「偏函数」的雏形。

⑦ 面试视角

问法一：手写深拷贝时，Date、RegExp、Map、Set 怎么处理？循环引用呢？
  • 思路统一：在递归出口之前加类型分支，用「新建同类型容器 + 逐成员递归」处理。
  • Date：new Date(src.getTime())；RegExp：new RegExp(src.source, src.flags)。
  • Map：新建 Map，遍历每个键值对，键和值都递归深拷贝后 set 进去；Set：新建 Set，逐项递归后 add。
  • 循环引用：递归入口先查 WeakMap 登记表——同一次拷贝里同一引用只建一次副本，命中直接返回；拷贝完成前先登记 map.set(src, cloned)。WeakMap 的弱引用特性保证不阻碍垃圾回收。
  • 加分项：提一句实际工程可直接用 structuredClone（原生深拷贝，但不支持函数），并说明手写版考察的是原理理解。
问法二：防抖和节流的区别？实现要点有哪些？
  • 语义区别：防抖 = 停止触发后 wait 毫秒才执行一次（重置闹钟）；节流 = 每 wait 毫秒最多执行一次（锁 + 定时解锁，或时间戳对比）。
  • 共同实现核心：闭包保存状态（定时器 id / 上次执行时间戳），返回一个包装函数。
  • 进阶参数：immediate（防抖首次立即执行）、cancel（取消 pending 的执行）；节流可选 leading / trailing（首尾是否触发）。
  • 选型口诀：等用户停下来用防抖（搜索联想、resize 重算）；持续动作保频率用节流（滚动加载、拖拽跟随）。
  • 加分项：指出防抖在「无限滚动触底」这种场景有饿死风险（用户一直滚动就永远不触发），此时必须节流。
