② 深入浅出

1. 为什么需要 TS：动态类型的隐患

纯 JS 里，function total(price, count) { return price * count; } 传进字符串也能「跑起来」，直到某天 price 是 "12元"，页面上赫然出现 NaN——错误暴露在运行时，而且往往在线上。TS 的做法是给值「贴类型标签」，让绝大多数错误在编译期（写代码与编译阶段）就被拦下；TS 最终仍编译成 JS 运行，所以它不改变运行时行为，改变的是「错误被发现的时机」。

2. 类型标注与类型推断

let count: number = 42;          // 显式标注
let name = '小李';                // 省略标注：TS 推断为 string，一样有检查
function total(price: number, count: number): number {
  return price * count;
}
total(12, '3');                  // 编译报错：string 不能赋给 number

推断能覆盖的场景不必手写标注；标注的价值在「函数边界」——参数与返回值是调用双方的契约，最值得写。

3. any / unknown / never 三兄弟

  • any：彻底放弃类型检查，any 值可以赋给谁、谁也能赋给 any，且错误会像涂改液一样把检查「传染」给下游。应急可用，不要常用。
  • unknown：安全的「万能接收型」——什么值都能装进来，但使用前必须先收窄（typeof / instanceof 判断或类型断言），否则编译报错。接接口返回值、第三方库未知数据时，用它替代 any。
  • never：没有任何值能赋给它的「底类型」。常出现在必然抛错或死循环的函数返回值上；配合联合类型的穷尽性检查，还能在「漏处理某个分支」时让编译报错。

4. interface 与 type、联合类型与字面量类型

interface User { name: string; age?: number }   // age 可选
type ID = string | number;                       // 联合类型：二选一
type Status = 'idle' | 'loading' | 'done';       // 字面量类型：把合法值枚举出来
let s: Status = 'loadingg';                      // 拼错 → 编译期就报错

interface 与 type 大部分能力重叠：描述对象/函数都行。差异点——interface 支持声明合并（同名自动合并，适合扩充公共契约），用 extends 继承；type 更灵活，能表达联合、字面量、条件类型等。团队统一一种即可。字面量联合类型是性价比最高的防呆手段：把「合法取值」列出来，拼错、乱传当场拦截。

5. 泛型入门：类型参数化

function firstItem<T>(arr: T[]): T {
  return arr[0];
}
const a = firstItem<number>([1, 2, 3]);   // a: number
const b = firstItem(['x', 'y']);          // 自动推断 T = string，b: string

泛型把「类型」变成函数的参数：一份逻辑，进出类型都跟着调用方的实际类型走，既不用为每种类型复制函数，也不会丢掉检查。

生活类比：超市自助结算机的扫码环节

小李推着购物车来到超市自助结算机。带条码的商品一扫即过——条码就是类型标注：机器当场就知道「这是什么、多少钱」，绝不会把牙膏记成洗衣液的价格。散装水果没条码？放上秤，机器自动识别品名与价格——这就是类型推断：你没写标注，TS 也推得出来。

要是有人把没贴条码的商品硬塞进扫码区，机器当场报警——错误在出门（上线）之前就被拦下，而不是回到家（线上运行）拆袋才发现买错了东西。结算机旁还有两条特殊通道：「免检通道」any，什么商品都扫得过，但小票对不上账——检查被彻底关掉，隐患全留到运行时；「待检区」unknown，也什么都能放，但必须先确权（过一次检查/收窄）才允许结账使用。至于 never，那是「永不放行」通道——世界上不存在能通过它的商品。

⑦ 面试视角

问法一：any 与 unknown 有什么区别？never 会在什么场景出现？
  • any：双向畅通且不检查——any 可以赋给任何类型，任何类型也能赋给 any，类型错误会顺着 any「传染」到下游，等于局部关闭了 TS。
  • unknown：只能接收、不能直接使用——调用方法或赋值给别的类型前必须收窄（typeof / instanceof / 类型断言），因此它是「安全的 any」。
  • 实践口径：不确定的数据（接口返回、第三方回调）一律先 unknown，收窄后再用。
  • never：没有任何值属于它；必然抛错或死循环的函数返回 never；在联合类型 switch 中用「兜底分支赋值给 never」做穷尽性检查，漏分支时编译报错。
问法二：interface 与 type 有哪些异同？枚举适合什么场景？
  • 相同：都能描述对象、函数、可索引结构，都支持扩展（interface extends / type 交叉号组合），大多数场景可互换。
  • interface 独有：声明合并——同名 interface 自动合并成员，适合给公共库「打补丁」扩展契约。
  • type 独有：能表达联合类型、字面量类型、元组、条件类型等非对象形态，表达力更强。
  • 枚举：适合一组相关的具名常量（如订单状态）且希望有命名空间与反向映射时；注意枚举会编译成真实的运行时对象，若只需要「合法取值约束」，字面量联合类型更轻量。
