② 深入浅出

一、为什么 JS 是单线程

设想两个线程同时改同一个 DOM 节点：一个要删、一个要改文字，听谁的？为避免这种竞态，JS 主线程从设计上就只有一条—— 一次只做一件事。慢活（网络请求、定时器、读文件）不自己干，而是交给浏览器的其他线程去办，办完把「回调函数」放进队列排队等主线程，这就是异步：单线程，但不傻等。

二、调用栈与任务队列

调用栈像厨师手里那口锅：函数调用就下锅，返回就出锅，同一时刻只能炖一锅。 异步操作的回调不会立刻执行，而是先排进任务队列；每当调用栈空了，事件循环（Event Loop）就从队列取队首的回调放进锅里执行——它是个永不停歇的调度员。

三、宏任务与微任务

队列其实不止一条。宏任务（macrotask）：setTimeout / setInterval 的回调、I/O、UI 事件回调等； 微任务（microtask）：Promise.then / catch / finally、queueMicrotask、MutationObserver。 执行规则只有一句话：当前任务（含最初的同步脚本）跑完 → 一次性清空全部微任务 → 取一个宏任务 → 再清空微任务 → 如此循环。页面的渲染穿插在宏任务之间进行。

四、混合输出题的推演口诀

① 先按行划出同步代码，立即执行；② 遇到 setTimeout 把回调记到「宏」栏，遇到 Promise.then 记到「微」栏； ③ 同步跑完后，先把「微」栏全部清空；④ 再取「宏」栏的一个执行，执行完又先清「微」栏。 记住「微任务永远插在下一个宏任务之前」，输出顺序就不会乱。

五、浏览器与 Node 的差异速览

Node 的事件循环由 libuv 驱动，分为 timers、poll、check 等多个阶段；Node 11 之前微任务在「阶段之间」统一执行，Node 11+ 已与浏览器对齐为「每个宏任务后清空微任务」。 另有区别：process.nextTick 的优先级高于普通微任务；主模块中 setImmediate 与 setTimeout(0) 的先后不确定，但在 I/O 回调内部 setImmediate 恒定先执行。

生活类比 · 事件循环像只有一名厨师的小馆子

店里规矩三条：第一，厨师只有一位（单线程主线程），一次只做一道菜，做完手里这道才腾出手；第二，服务员把新订单（宏任务，如 setTimeout 的回调）贴到订单墙上排队，厨师按先后取单； 第三，灶台边贴着 VIP 小抄（微任务，如 Promise.then），规矩是每做完一道菜，必须先把灶台上所有小抄一张不剩全部处理完，才允许去订单墙拿下一张。 所以哪怕订单墙的第一张单比小抄来得早，也得等小抄清完——这就是「微任务插队」。 开业后厨师做的第一件事是「同步脚本」，它就像开业第一单，做完才开始一轮轮「清小抄、取订单」的循环。

④ 知识联结

前置依赖：JS 类型、作用域与闭包——回调函数被闭包「记住」的变量，正是它进队出队后仍能正确工作的原因。

向后延伸：微任务的制造者 Promise 是异步编程的主角，直接衔接Promise 与 async/await； Node 把事件循环搬到了服务端并加了阶段机制，见Node.js 运行时与事件循环。

交叉链接：

  • 小程序双线程架构 —— 逻辑层单线程 + setData 通信，同样是「任务排队、跨线程传话」的思想
  • 运行时优化：防抖、节流与计算缓存 —— 防抖节流全靠 setTimeout 的宏任务排队实现，理解事件循环才能用对
  • Promise 与 async/await —— await 之后的代码本质是被排进微任务队列的回调

⑦ 面试视角

问法一：下面代码输出什么？（setTimeout 与 then 链混合） 
setTimeout(function () { console.log('T'); }, 0);
Promise.resolve()
  .then(function () { console.log('P1'); })
  .then(function () { console.log('P2'); });
console.log('S');
  • 输出 S、P1、P2、T：S 是同步代码；T 进入宏任务队列；then 链的第一段进入微任务队列。
  • 同步跑完后清空微任务：先 P1；P1 执行完才把 then 链的第二段排进微任务队列，随即清空 → P2。
  • 微任务全部清完，才取宏任务队列里的 T。哪怕 setTimeout 写 0 毫秒，也要等这一切结束。
  • 加分项：then 的回调不是注册时入队，而是「前一段兑现后」才入队——说出这一点能明显加分。
问法二：JS 单线程为什么还能高效处理异步？浏览器与 Node 的事件循环有何差异？
  • 单线程只指 JS 主线程：耗时操作（网络、定时器、I/O）由浏览器/系统的其他线程完成，完成后再把回调排进任务队列。
  • 事件循环负责调度：调用栈空 → 清空全部微任务 → 取一个宏任务 → 再清微任务，循环往复；页面渲染穿插在宏任务之间。
  • Node：libuv 分 timers / poll / check 等阶段轮转；Node 11+ 与浏览器对齐为每个宏任务后清空微任务，老版本是按阶段统一清。
  • Node 特有：process.nextTick 优先级高于 Promise 微任务；主模块里 setImmediate 与 setTimeout(0) 顺序不确定，I/O 回调内 setImmediate 恒定先执行。
  • 加分项：能顺带提 requestAnimationFrame 在渲染前执行，说明对「每一帧」的调度也有概念。
