② 深入浅出

一、Hybrid 架构：原生壳 + WebView

Hybrid（混合）开发的结构一句话能说清：原生 App 当壳，里面放一个 WebView（内嵌浏览器）， 业务页面用 H5 写。壳负责安装、启动、推送、支付这些必须原生的部分； 页面内容走 H5，改版不用重新发版上架，服务端发新版网页就生效。 这是历史上最成熟的跨端方案：客户端开发快、多端复用度高， 但性能受 WebView 上限约束，复杂动画与长列表的流畅度天然不如原生。

二、JSBridge 的两条通道

WebView 里的网页默认是个「笼中鸟」：JS 只能在页面里活动，碰不到相机、通讯录这些原生能力。 JSBridge 就是笼子上开的一扇受控的门，H5 调原生主要有两条通道：

  • URL Scheme 拦截：H5 发起一个约定格式的特殊请求（如改 iframe 的 src）， 原生侧拦截这个请求、解析出要调的方法和参数。兼容性好、上手简单， 但消息要塞进一个 URL 字符串里，有长度限制，高频调用也容易排队堵车。
  • 注入 API：原生在 WebView 的 window 上挂一个约定名字的对象和方法 （Android 的 addJavascriptInterface、iOS WKWebView 的 scriptMessageHandler 都是这类）， H5 直接调用它，参数结构化传递，没有 URL 长度之忧，是现代方案的首选。

三、双向通信：回调 id 是怎么转起来的

真实调用是异步的：H5 发出「读设备信息」的请求后不能卡住干等，原生处理完还要把结果送回来。 业界通行做法是两张表 + 一个编号：原生侧维护「注册表」——名字到处理函数的映射， 收到消息先查表，找到处理人就执行；H5 侧则维护「回调表」——发消息时生成一个回调 id， 把回调函数按 id 存起来，把 id 一起塞进消息体。原生干完活，凭这个 id 反向调用 H5 的回调， 结果就回到了发起调用的那行代码。此外原生也会主动通知 H5（推送、页面生命周期等）， 走的是同一座桥，只是方向相反。

四、离线包与热更新

H5 页面第一次打开要联网拉资源，弱网时白屏很久。Hybrid 的经典优化是离线包： 把页面框架、JS、CSS 打成一个包，提前随 App 下发或后台静默更新，打开时直接从本地加载， 只在线请求真正的业务数据——首屏速度大幅提升。这也带来了热更新能力： 业务页面不走应用商店审核即可迭代，绕开发版周期。当然包的校验与更新流程必须有签名机制兜底， 否则等于给自己开了个后门。

生活类比：景区观光小火车与车厢对讲机

把 App 想成一座景区，Hybrid 就是景区的观光小火车：车身、发动机、刹车都是景区自己的 （原生壳：安装、推送、支付这些硬能力必须原生），而车厢里今天坐一批游客、明天换一批， 谁上车谁下车景区说了不算——那就是 H5 内容，随时换、不用把整辆车送回厂重造（不用重新发版）。

车厢和驾驶室之间装了一台对讲机，这就是 JSBridge。乘客按下对讲机喊： 「车厢太热了，开个空调」——司机拿起频道表查了一眼：「空调」这个频道登记在他名下， 于是拧开开关照做（H5 发消息，原生查注册表找到处理人）。司机也会主动喊话： 「前方急弯，请坐稳」（原生事件通知 H5）。对讲机喊话要报一个「座位号」 （回调 id），司机处理完对着座位号回话，喊话的那位乘客才知道事情办完了。 最关键的是频道表必须严管：只登记景区自己人的频道、核对话筒是谁递过来的 （白名单与来源校验），否则任何一个游客都能对着对讲机喊「打开车门」——那就是安全事故了。

交叉链接：

  • Web 安全：XSS、CSRF 与 CSP —— JSBridge 的白名单、来源校验与最小授权，和 Web 安全的防御思想一脉相承。

⑦ 面试视角

问法一：讲讲 JSBridge 的实现原理，H5 与原生如何双向通信？
  • 两条通道：URL Scheme 拦截（H5 发特殊请求、原生拦截解析，简单但有长度与并发限制）；注入 API（原生往 window 挂对象，H5 直调，结构化参数，现代首选）。
  • H5 → 原生：消息体带方法名、参数、回调 id；原生按名字查「注册表」找到处理函数执行。
  • 原生 → H5：执行完毕后凭回调 id 反查 H5 的「回调表」，调用对应回调把结果送回发起处。
  • 原生主动通知（推送、生命周期等）走同一座桥、方向相反。
  • 加分项：能对比两条通道的取舍，并指出离线包让 H5 首屏摆脱网络、实现绕开发版的热更新。
问法二：JSBridge 有哪些安全风险？该如何防护？
  • 核心风险：Bridge 等于把原生能力开门揖盗，任意网页拿到它就可能调相机、读文件、发起支付。
  • 来源校验：只对白名单域名 / 校验过签名的页面开放 Bridge，第三方页面直接隔离。
  • 最小授权：注册表按需暴露，敏感 API（支付、登录态）增加二次鉴权与用户确认。
  • 参数与回执校验：对参数做校验防注入，回执内容避免携带超出所需的敏感数据。
  • 加分项：提到离线包必须配签名校验，否则更新通道本身会成为被投毒的后门。
