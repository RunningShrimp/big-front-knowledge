② 深入浅出

一、事件委托：把监听器从 N 个减到 1 个

点击页面上最深的那个元素时，事件并不会只发生在它身上，而是分三段走：捕获（从外向内）→ 目标阶段（真正被点的元素）→ 冒泡（从内向外逐级上浮，默认监听就挂在这一段）。 事件委托正是「搭冒泡的顺风车」：在共同父节点上只绑 1 个监听器，等子元素的事件冒泡上来统一处理。 写法上要认清两个角色：e.target 是「真正被点到的最深元素」，e.currentTarget 是「挂着监听器的元素」； 因为点击目标可能是按钮里更深的 span，实际代码几乎总是用 e.target.closest('.xxx') 从最深处向上找回「业务节点」。

  • 优点：1000 个列表项只需 1 个监听器（省内存）；动态新增的子元素天然被覆盖，不用重新绑定；销毁时只解绑一处。
  • 局限：前提是事件会冒泡——blur、mouseenter/mouseleave 这类不冒泡的事件委托不了（可改用 focusin/focusout 或捕获阶段监听）；另外 e.target 可能比你预期的更深，漏写 closest 就会「点子元素失灵」。

二、发布订阅与观察者：先分清，再动手

两个模式都解决「一件事发生后，谁需要知道」，区别在有没有中间人： 观察者模式里，目标（Subject）直接持有观察者列表并逐个调用其更新方法，双方彼此认识（耦合）； 发布订阅模式则多了一个「事件中心」：发布者只管往中心喊（emit），订阅者只管向中心登记（on），双方互不相识，靠事件名解耦。 手写四件套的要点：on 往「事件名 → 监听器数组」里 push；off 用 filter 按引用移除； emit 遍历前先 slice 拷贝数组（否则执行中某个 once 把自己删掉，后面的监听器会被跳过）； once 订阅的是一个包装函数，触发时先移除自己再执行原函数——解绑时比对的必须是包装函数本身。 完整的判题级实现见手写题·异步篇的例题。

三、序列化进阶：JSON.stringify 的暗坑

JSON.stringify 是 localStorage 存储与接口通信的标配，但它有几条「暗规则」经常出现在追问里：

  • 对象里的 undefined、函数、Symbol：整个键被丢弃；同样的值出现在数组里则变成 null（为了保持索引对齐）。
  • Date 变 ISO 字符串；NaN / Infinity 变 null。
  • 循环引用直接抛 TypeError（Converting circular structure to JSON）——原生宁可报错也不输出残缺数据。
  • 手写简版的思路：按类型分支（string / number / boolean / null / 数组 / 对象）递归拼字符串，遍历对象时用 hasOwnProperty 只看自身属性；若要支持循环引用，思路与深拷贝相同——用 WeakMap 登记已见对象，再次遇到就抛错或输出占位。

四、延伸考点速览：手写 Ajax 五步

事件委托之外，浏览器手写的另一个常客是 Ajax：XHR → open(method, url, true) → 监听 onreadystatechange（或 onload）并判断 status 为 2xx → send(body) → 读取 responseText。高频追问是把它Promise 化封装：成功 resolve 响应、失败（网络错或非 2xx）reject， 这正好用上Promise 一页的知识。

生活类比 · 老小区装上快递柜：快递员再也不用挨家挨户敲门

没有快递柜的年代，快递员要挨家挨户敲门送件——100 户就是 100 次打扰（1000 个列表项绑 1000 个监听器），而且常常吃闭门羹：住户不在家，件就送不出去（子元素还没渲染出来，逐个绑定直接失败）。

小区装上快递柜之后画风一变：快递员把所有件统一投进柜子（事件只绑在共同的父节点上），完全不用关心谁住在几零几；住户回家看到柜子亮灯（事件顺着 DOM 树冒泡到父节点），凭取件码认领自己的件——取件码就是 e.target，顺着柜格号找到住户就是 closest()。

最妙的是：新住户搬进来（动态新增的 DOM 节点）根本不用去物业登记，柜子照收他的件——这就是「委托对动态子元素自动生效」。但也别神化快递柜：有些物品它收不了（不冒泡的事件，比如 blur），还得专人直送（直接绑定或改走捕获阶段）。记住准确结论：委托的前提是事件冒泡，判断来源永远以 e.target 为准，定位业务节点用 closest。下面这个演示，请你当一回班主任。

⑦ 面试视角

问法一：事件委托的原理、优点和局限分别是什么？
  • 原理：利用事件冒泡，在共同父节点上只绑 1 个监听器；用 e.target 找到真正被点的最深元素，再用 closest 向上定位业务节点。
  • 优点：监听器数量从 N 降到 1（省内存）；动态新增子元素天然被覆盖、无需重绑；销毁时只需解绑一处。
  • 局限：前提是事件会冒泡——blur、mouseenter/leave 委托不了（可用 focusin/focusout 或捕获阶段替代）；e.target 可能是更深的子节点，漏写 closest 会失灵。
  • 经典场景：长列表每行的「删除」按钮、表格单元格点击、千级以上 DOM 的交互监听。
  • 加分项：说明 e.target 与 e.currentTarget 的区别（最深被点元素 vs 挂监听器的元素）。
问法二：发布订阅和观察者模式的区别？once 和循环引用序列化怎么处理？
  • 观察者模式：目标直接持有观察者列表并调用其更新方法，双方耦合；发布订阅多了「事件中心」，发布者与订阅者互不相识，靠事件名解耦。
  • once 实现：订阅一个包装函数，触发时先把自己从监听数组移除、再执行原函数；解绑比对的是包装函数本身，不是原函数。
  • emit 细节：遍历前 slice 拷贝数组，防止执行中 once 自删导致后续监听器被跳过。
  • 循环引用序列化：原生 JSON.stringify 直接抛 TypeError；手写可用 WeakMap 登记已见对象，再次遇到同一引用就抛错或输出占位标记。
  • 加分项：提到 Vue 的依赖收集更接近观察者（Target 直依赖 Dep），而全局事件总线 mitt/EventEmitter 是典型发布订阅。
