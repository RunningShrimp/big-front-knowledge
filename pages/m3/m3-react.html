② 深入浅出

一、心智模型：UI = f(state)

老写法（如 jQuery）是「找到那个 <span>，把它的文字改掉」——你得自己维护几十处「改 DOM 的命令」。 React 换了个思路：把「界面长什么样」写成状态的函数。state（数据）是输入，UI（界面）是输出； 数据一变，React 重新执行一遍组件函数，算出新虚拟树，Diff 后只把变化的部分更新到页面。 整条链路永远是单向的：state → 视图 → 用户事件 → setState → 重新渲染。你从不下场改 DOM，只改数据。

二、组件与 props：一份只读的契约

组件是「接收 props、返回界面」的函数。props 是父组件传进来的原料，约定是只读： 子组件不能偷偷改 props，只能通过回调通知父组件去改 state——数据从上往下流，改动请求从下往上报，方向不混。 表单里也有个经典选择：受控组件把输入框的值交给 state 管（value 来自 state，onChange 回写）； 非受控组件让 DOM 自己保存输入，需要时再用 ref 去取。受控是默认推荐，因为「数据只有一份源头」。

三、Hooks：函数组件的「瑞士军刀」

函数组件本来没有记忆，Hooks 给它补上了能力，常用的五个各管一摊：

  • useState(初始值)：声明一块可变状态，返回「当前值 + 修改函数」。
  • useEffect(函数, 依赖数组)：处理副作用（请求数据、订阅、改标题），依赖不变就不重复执行，返回的函数用于清理。
  • useMemo(计算函数, 依赖)：依赖没变就复用上次算好的结果，避免昂贵重复计算。
  • useCallback(函数, 依赖)：让函数引用在依赖不变时保持稳定，常配合子组件减少无谓重渲染。
  • useRef(初始值)：一个跨渲染存续的「盒子」，改它不触发重渲染，也用来直接抓 DOM 节点。

四、常见陷阱：都是「快照」惹的祸

闭包旧值：每次渲染都是一次独立的函数执行，那一帧里的 count 是个常量。 定时器、事件回调如果捕获了旧帧的 count，3 秒后读到的仍是旧数字。 依赖数组漏写：useEffect 声明「只在依赖变化时重跑」，漏写依赖就是骗 React「不用重跑」，读到的自然是旧值。 不必要的重渲染：父组件一渲染，子组件默认跟着渲染；列表大、计算重时，用 useMemo/useCallback、拆状态做减法。

生活类比 · 点单机与后厨规程

React 像一台点单机。你是顾客（开发者），只负责改订单（setState），从不冲进厨房亲手端菜； 厨房（React）看到订单变了，就按新订单整个重出一份菜（重渲染出新虚拟树）， 但传菜口会对比新旧两份，只把变了的菜端上桌（Diff + Patch），没变的纹丝不动。

Hooks 则是后厨的操作规程：调料盒严格按「出餐时要用的先后顺序」摆成一排，厨师每次取料都按同样的次序 拿第 1 格、第 2 格、第 3 格。谁要是把某个调料盒收进了柜子（把 Hook 写进 if，某次渲染不执行）， 后面所有的取料就整体错一位——盐当糖用，菜全毁。这就是「Hooks 不能写在条件分支里」的真正原因。

⑥ 巩固复习

一句话讲给外行听：React 像点单机——你只管改订单（数据），厨房自动按新订单重新出餐（界面跟着变）； 而 Hooks 的规矩是「调料按固定顺序摆、按固定顺序取」，谁乱插队，整锅菜的味道就全串了。

建议复习时间：今天睡前把「state → 视图 → 事件 → setState → 重渲染」复述 1 遍，1 天后、3 天后、7 天后各回来重做例题（对应遗忘曲线 1/3/7 天间隔），站点会在地图页标出「该复习了」。

⑦ 面试视角

问法一：useEffect 和类组件的生命周期是怎么对应的？
  • 依赖数组为空 []：只在挂载后执行一次，近似 componentDidMount。
  • 有依赖且依赖变化时重跑：近似 componentDidUpdate（但它先比较依赖，变了才跑）。
  • 返回的清理函数：在下次 effect 执行前与卸载时调用，近似 componentWillUnmount（订阅解绑、清定时器都靠它）。
  • 加分项：不要机械照搬生命周期心智——useEffect 的本质是「让副作用与依赖保持同步」，一次渲染对应一次同步机会。
问法二：为什么 Hooks 不能写在条件分支、循环里？
  • React 靠「调用顺序」记账：每个 Hook 在首次渲染时按顺序领到自己的状态槽（类似内部链表节点）。
  • 重渲染时 React 只按顺序逐个取回，完全不认识变量名；若某次渲染少调了一个 Hook，后面全部错位，状态张冠李戴。
  • 开发环境下 React 会检测到 Hook 数量/顺序变化并直接抛错拦截。
  • 正确做法：把条件逻辑写进 Hook 内部（如 useEffect 的依赖判断、useState 存布尔值），而不是条件地「调不调用」Hook。
