② 深入浅出

一、响应式要解决什么

朴素写法里，「改数据」和「改界面」是两件事：改了 user.name，还得自己记得去改 span.textContent，漏一处就是 bug。 响应式的目标只有一个：数据一变，用到它的视图自动更新。要达成它，框架必须回答两个问题： 第一，怎么「拦截」到数据被读、被写？（侦测）第二，界面哪几个部分在用这条数据？（依赖）。

二、Vue 2 的方案：Object.defineProperty 逐个劫持

Vue 2 用 Object.defineProperty(data, key, { get, set }) 把每个属性改造成「带监控的存取器」： 读取时走 get（顺便做依赖收集），写入时走 set（顺便派发更新）。思路优雅，但有三个先天缺陷：

  • 新增 / 删除属性监听不到：getter/setter 必须在属性「已存在」时才能定义，事后 data.newKey = 1 走的是普通赋值，框架毫无感知。Vue 2 只能提供 $set / $delete 这类补丁 API。
  • 数组是重灾区：下标赋值 arr[0] = x 和改 arr.length 无法被劫持，Vue 2 干脆重写了 push、splice 等 7 个数组方法来兜底。
  • 初始化开销：必须在组件初始化时递归遍历 data 的所有层级、所有属性逐一劫持，数据又大又深时这一步很贵。

三、Vue 3 的方案：Proxy 整体代理 + 惰性响应式

Vue 3 改用 new Proxy(data, handler)：它代理的是「整个对象上的操作」，get、set、has、deleteProperty 等 13 种拦截器随取随用。 于是新增、删除属性天然可感知，数组下标和 length 也直接拦截，$set 彻底退场。 另一个大优势是惰性：初始化只包一层 Proxy，嵌套对象要等到真正被访问时才转成响应式，深山大对象不再一次全部扫描。

四、依赖收集与派发更新：track 与 trigger 的接力

拦截到了读写，还差「通知谁」。Vue 的做法是：谁运行时读了我，我就记住谁。 每个用到数据的渲染函数 / 副作用（effect）运行时，读到 state.count 触发 get 拦截， Vue 执行 track：把当前 effect 记为 count 的订阅者（内部用 WeakMap → Map → Set 三层结构按「对象 → 属性 → 效果」存表）。 之后 state.count = 新值 触发 set 拦截，执行 trigger：按表查出订阅者，逐个重新执行。 新一轮渲染又读新值、又收集新依赖——闭环就转起来了。

生活类比 · 两家装修公司的传感器方案

响应式就像全屋智能：数据一变（有人推门），灯自动亮（视图更新）。Vue 2 的 defineProperty 像装修公司 A： 只给图纸上本来就有的门窗装传感器——入住后新开一扇门（新增属性），门上没传感器，推开也无人知晓； 而且必须开工时一次性把全屋装满（初始化递归遍历），房子越大前期越费劲。

Vue 3 的 Proxy 像请了一位全天候管家站在入户处：任何人从任何门进出、搬动任何家具（get / set / delete）他都记录在案； 还是「随叫随到」式服务——你走到哪个房间，他才跟进哪个房间布防（惰性代理），没去过的储物间他绝不提前折腾。

五、ref 与 reactive 怎么选

reactive(obj) 基于 Proxy，只能包对象、数组这类「能被代理的东西」，基本类型（数字、字符串）拦不住。 所以单个值要用 ref(值)：它把值装进 { value } 这个小对象里，靠 value 的存取器实现响应式——这就是为什么 ref 在 JS 里必须写 .value。 经验法则：成体系的对象 / 列表用 reactive 或 ref 包对象皆可；独立的单值、需要整体替换的值、要在函数间传来传去的值，用 ref 更稳妥。

④ 知识联结

前置依赖：虚拟 DOM 与 Diff 算法——响应式只负责「知道谁变了、通知谁」， 真正落到页面的那一下仍是新旧虚拟树 Diff + Patch，两者是一条流水线的上下游。

向后延伸：有了响应式的地基，组件如何消费数据就是下一个话题： 组件设计原则讲 props 与状态边界；跨组件共享时，Pinia 一类方案的思想在 状态管理思想里展开。

交叉链接：

  • ES6+ 核心语法 —— Proxy、Reflect、Map/Set、WeakMap 是 Vue 3 响应式的全部积木。
  • 对象与原型 —— Object.defineProperty、属性描述符这些 Vue 2 的底层工具在这里讲透。
  • React 核心与 Hooks —— 两种自动更新的路线对比：React「数据变就整棵重算」，Vue「先精确知道谁变了再小范围动」。

⑦ 面试视角

问法一：Vue 2 和 Vue 3 响应式的核心区别有哪些？
  • 侦测手段：Vue 2 用 Object.defineProperty 逐属性劫持 get/set；Vue 3 用 Proxy 在对象层面整体代理 13 种操作。
  • 能力差异：Vue 2 监听不到新增/删除属性（要 $set/$delete 补）与数组下标、length 赋值（重写 7 个方法兜底）；Vue 3 天然全覆盖，$set 退场。
  • 初始化成本：Vue 2 递归遍历整个 data；Vue 3 惰性——嵌套对象访问到才转响应式，首屏开销更小。
  • 依赖存储：两者思路一致（读时收集 track、写时派发 trigger），Vue 3 用 WeakMap → Map → Set 存「对象 → 属性 → 副作用」。
  • 加分项：Proxy 无法 polyfill 到老浏览器，这是 Vue 3 放弃 IE 的直接原因之一。
问法二：ref 和 reactive 有什么区别？实际项目里怎么选？
  • reactive 基于 Proxy，只能代理对象 / 数组 / Map 这类引用类型；基本类型（number、string、boolean）无法被 Proxy 拦截。
  • ref 把值装进 { value } 包装对象，靠 value 的 get/set 实现响应式，所以任何类型都能包；在 JS 里读写必须 .value，模板里自动解包。
  • reactive 有个易踩的坑：解构或整体替换后会失去响应式连接（拿到的是普通值/新对象）。
  • 选择经验：独立的单值、需要整体替换或跨模块传递的状态用 ref；成组的对象/列表状态两者皆可，团队统一即可。
